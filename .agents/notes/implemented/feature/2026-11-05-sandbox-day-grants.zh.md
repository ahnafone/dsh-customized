# Agent Note: 面向跨目录工作的按日沙箱授权

Status: implemented

[English](2026-11-05-sandbox-day-grants.md) | 中文
## Problem

沙箱升权提示此前只提供一个授权按钮 `Allow once`。当用户跨多个目录工作时，同一个包含性拒绝会在每次调用时重复出现，因为升权授权随发起调用的结束而失效。[审批 seam 的 Agent Note](2026-07-06-approval-seam.zh.md) 将更长期选项推迟到授权存储、作用域标识和撤销机制设计完成之后；本笔记记录该设计。

## Decision

沙箱升权可以在 `allowed-once` 之外提供一个更长期作用域 `day`（24 小时）。审批 seam 传递用户选择；沙箱层将会话日志作为持久化存储；在授权未过期期间，`ctx.sandboxPolicy.resolve()` 会放宽后续调用。

### 审批决定

`ApprovalOutcome` 增加 `'allowed-day'`，`ApprovalRequestEvent` 增加可选的 `grants` 列表，声明请求方能够兑现的作用域。`ApprovalService.request()` 只在请求声明了对应作用域时接受作用域结果，否则会把未声明的作用域结果归一化为 `'unavailable'`，因此应答者无法凭空制造更长期授权。审计事件对记录归一化后的决定。该 seam 不在请求之间存储任何内容；与 `allowed-once` 一样，持久化由发起请求的消费方负责。

### 授权及其作用域

`approveEscalation` 返回 `EscalationDecision`。在 `workspace-write` 下，能够识别出目录的文件写入或编辑会提供**目录授权**：`Allow once` 和按日操作都会在该次调用中使用常驻模式加该目录作为额外可写根目录，而按日操作还会记录该目录。目录优先取组合中存在 `ctx.workspaceRegistry` 时包含目标的最具体已注册工作区根目录，否则取目标最近的已存在父目录；文件系统根目录永远不符合条件。bash、pwsh、PTC、plugin-manager、`apply_patch`，以及无法确定目录的写入/编辑则提供**模式授权**，授予所请求的模式。

更长期授权是一条仅记录日志的 `sandbox/grant` 事件（模式或物理目录，加上绝对过期时间），`/permission revoke` 写入 `sandbox/grant-revoke`。`sandboxGrants` 投影折叠两者；`resolve()` 用最宽的未过期模式授权放宽常驻模式，并把未过期的目录授权追加到 `additionalWritableRoots`，因此同一策略同时到达文件系统围栏和 shell 执行器。运行时上下文快照会列出每条活动授权及其过期时间，让模型知道该访问是临时的。

### 撤销

任何 `sandbox/mode` 事件——权限预设切换或模式变更，包括委派种子事件——都会在折叠中清空所有活动授权，因为之后常驻模式的决定不能被静默覆盖。`/permission revoke` 在不改变常驻模式的情况下清空授权。过期在 `resolve()` 读取投影时判断；读取路径绝不写入事件，过期授权只是不再放宽策略。授权按会话生效，随日志回放，并且不会被子 agent 会话继承——子 agent 在委派时只收到模式种子。

### 通道与范围限制

Web 客户端是唯一的授权界面。ACP 桥接层和 SDK 保持一次性词汇：它们忽略 `grants` 声明，无法记录更长期授权。不存在 `allow_always` 的 profile 级存储；新会话从零授权开始。按日时长是固定的协议词汇，而非部署配置，按钮文案就是“1 天”。

## Alternatives considered

- **Profile 级持久授权（`allow_always`）**——暂不采用：它需要持久 profile 存储、撤销界面和跨工作区身份规则；所请求的按日作用域可由会过期的会话授权满足，而会话日志已经提供回放与审计，无需新增存储。
- **仅以会话沙箱模式作为授权**——不采用：把会话切换到 `danger-full-access` 一天会授权所有目录，而用户要求的是一个目录。目录授权让升权保持最小权限；在无法识别目录时仍保留模式授权作为回退。
- **复用 `sandbox/mode` 并增加 `expiresAt` 字段**——不采用：旧读取器会把该事件解释为永久模式覆盖，从而静默放宽到超过预期的一天。新的必需事件让旧读取器拒绝会话，而不是错误解释。
- **改为配置 `additionalWritableRoots`**——不采用：那是所有会话共享的部署配置，不是针对某个会话记录的用户决定；它无法按用户操作过期或撤销。
- **使用 `ctx.userQuestions` 承载多选项提示**——不采用：审批 seam 拥有权限提示、失败关闭的缺失规则和审计事件对；问卷表单会重复该策略并丢失闭合的结果词汇。
- **让一次性目录请求仍使用所请求的模式**——不采用：两个按钮会在作用域和时长上都不同，“允许一天”可能比“允许一次”更窄；现在两者都解析为同一目录作用域。

## Consequences

- 新的 `sandbox/grant` 与 `sandbox/grant-revoke` 事件类型是必需事件：早于本变更的读取器会拒绝包含授权的会话，而不是静默丢弃或重新解释权限。`SESSION_FORMAT_VERSION` 保持不变，因为拒绝是安全的结果。
- 目录授权是真实的额外可写根目录；如果目录在授权活动期间消失，强制执行会持续抛出 `SANDBOX_INVALID_ROOT`，直到授权过期或被撤销。
- 目录推断是尽力而为的。已注册工作区查找需要 `ctx.workspaceRegistry`；路径与主机工作区不匹配的远端执行环境会回退到父目录，而没有已存在父目录的操作会提供模式授权。
- 当能够识别目录时，一次性文件系统升权现在按目录生效；这比模型请求的 `danger-full-access` 更窄，是同一拒绝的最小权限解法。
- 权限预设切换会清空活动授权；希望在保留常驻模式的同时放弃授权的用户使用 `/permission revoke`。

## Testing

单元测试覆盖授权声明校验与审计结果、升权决定与目录/模式分支、授权折叠/过期/清空与上下文渲染、目录推断与授权后执行、每个强制执行族的授权写入、客户端按日按钮，以及 `/permission revoke`。Web 审批场景会以无需密钥的方式刷新多出按钮的 UI golden，另有一个仅回放的浏览器用例点击按日操作并断言记录的授权事件。
